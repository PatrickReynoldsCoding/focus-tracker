# Roadmap and decisions

Handoff notes so a fresh Claude session has the context this project was designed with. The owner is Paddy.

## Why this exists

Paddy juggles several coding projects, job-search goals and house maintenance, and loses track of anything he has not touched for a few days. He picks work on feel each morning and wants structure. The app picks one focus project per day, shows its next action and last note, and makes stopping cheap: one line on where he stopped, then he can let it go.

## Constraints and preferences

- Free to run: Google Sheets + Apps Script, deployed as a web app only he can open. Works on every device. Desktop is the main target, phone should be usable.
- Frictionless: open it and it works. Few clicks.
- Separation of concerns, plugin style: a small core and one folder per feature. Adding or removing a feature is a folder plus one config line. See AGENTS.md.
- Data readable by humans and by Claude: sheet tabs and plain markdown notes, no opaque blobs.
- Never link or copy sensitive Drive material. See AGENTS.md. Never commit his real links or ids.
- Excalidraw whiteboards per project (done, 2026-10-28; named, several per project since the Settings change): whiteboard module. React 18.2.0 and @excalidraw/excalidraw 0.17.6 load from jsDelivr only when a whiteboard opens. Saves `<mode folder>/Whiteboards/<project>-<id>.excalidraw` two seconds after a change and on close; reopens where you left off. Checked in real Chrome (draw, autosave, close, reopen).
  - Phone (2026-10-28): the desktop-only gate is gone. Excalidraw 0.17.6 has its own touch layout (top toolbar, bottom menu with undo/redo, hand tool). Tested with finger drawing (rectangle and freehand), pinch zoom, autosave, Save and close, and reopen, in Playwright Chromium mobile emulation (393x851, touch) and in real Chrome 124 on the Android 10 emulator (`com.android.chrome`, driven over DevTools). The page does not zoom or scroll sideways. The whiteboard bar is one slim line on phones; `touch-action: none` and `overscroll-behavior: none` on the shell stop pull-to-refresh while drawing. Not checked on a real phone: palm rejection, stylus, the on-screen keyboard with the text tool, and long-press behaviour. The Excalidraw menu still shows its own GitHub/Discord/Twitter links and "Reset the canvas", as on desktop.

### Batch 1: quick wins (done, 2026-10-28; tested with fakes only, not yet on Google's runtime)
Decisions Paddy made while it was built:
- Pomodoro breaks count as session time. Only Pause stops the session clock (and the pomodoro).
- When a work or break period ends, it alerts and then waits for a click ("Start break" / "Start work"). It does not move on by itself.
- The pomodoro is off by default and is switched on per session. Lengths are kept in user properties. A changed length applies from the next period.
- The Log has a `minutes` column: worked minutes without pauses, written on finish.
- The alert ticks on every tab while a session runs, not only on Today.
- No browser notifications: Chrome denies them inside the Apps Script iframe (tried 2026-10-28, even with the permission set by hand). Instead a period ending plays a sound made with Web Audio: a chicken when work ends (break starts) and a steam whistle when a break ends (work starts). The Pomodoro lengths dialog has buttons to try both. The tab title still blinks.

Original requests:
- Desktop: a small icon at the right to stretch the page to full screen width (remember the choice per browser).
- Projects table: sortable and filterable (by category, status, text).
- Kanban: remove the single "new task" bar. Each column has its own add-task control.
- Today: when a session is started, allow pause, and a simple pomodoro timer (work/break lengths configurable, default 25/5). Session time excludes pauses. State is stored server side so it survives switching devices. Alert with sound and tab title, because browsers may block notifications inside Apps Script pages.

### Speed, undo and editing (done, 2026-10-28, requested by Paddy)
- Duplicate cards were real: while a save was slow (about 1.5 s on Apps Script) the text stayed in the box, so a second Enter saved it twice. Now new cards show at once with an id made in the browser, the box clears, and the server refuses a repeated id.
- Speed: each sheet tab is read once per request and writes keep that copy up to date (sheetdb.js), header and rows come in one read. Sheet calls fell from 86 to 44 to open the app and from 44 to 12 to add a card. Card add, move, edit and delete show on screen first and save in the background, one save at a time and in order; a reply's data is only used when no later save is waiting. The browser warns before closing the tab while saves are pending.
- Undo: every call records its row changes; they are kept in the mode's Undo tab (last 30) and Undo (now in Settings) or Cmd/Ctrl+Z puts the newest back. Deletes are immediate with an Undo button in the message. Notes, whiteboards and the Today session are not undone.
- Drag and drop (SortableJS 1.15.2 from jsDelivr, short press on touch) replaces the move arrows on boards and lists, including order inside a column. The card dialog has a Column/Group choice as well.
- Panels can be hidden in Edit layout ("Hide", then "Show ..." in the bar). Lists have a colour: "⚙ Settings" on a list (Lists tab and Today) opens name, colour swatches with a live preview of the list, and Show on Today. A coloured list has a solid top bar and a tint. The project form has "+ New category…". Enter saves inline name fields.

### Local cache, offline queue, last page (built 2026-10-28, requested by Paddy; checked in jsdom and real Chrome, not on Google or a phone)
- The page remembers the page it was on (tab or project, per mode) in this browser only, and a reload returns to it. A deleted or locked project falls back to Today. Switching mode starts on Today.
- A saved copy of each mode's data (IndexedDB, then localStorage, then memory) draws at once with "Updating…" while the fresh data loads, and is ignored if its `SCHEMA` number differs.
- While the connection is down, card, checklist, sticky note, list, notes and project edits are kept on the device (queue survives a reload), shown as "Offline · N waiting", and sent in order when it returns. Anything else says "You are offline" and is not queued.
- Rows carry `updated_at` (Projects, Tasks, Criteria added to the sheet automatically). A queued edit that finds its row changed elsewhere keeps the newer version and logs the other in the Log tab; notes keep the older text as a conflict copy file. Details and limits: docs/offline-design.md.
- The honest limit: Apps Script serves the page, so it still cannot open cold with no signal. That needs the GitHub Pages route (docs/future-github-native-spike.md and the wrapper site).
- Untested on real devices: what `google.script.run` does with a dead connection (the code treats network-like messages, `navigator.onLine === false`, or 30 seconds without an answer as offline), and whether browser storage survives between visits inside the Google sandbox on the phone.

### Redo for data changes (done 2026-10-28, requested by Paddy)
- The header has Redo next to Undo (Ctrl or Cmd + Shift + Z, or Ctrl + Y). Undoing a change records the opposite change while the rows are put back, and keeps it in the same Undo tab as a row with `kind` = `redo` (new column, added automatically). Redo puts it back and returns the change to the undo list. Any new change clears the redo rows (no extra sheet read: `saveUndo_` already reads the tab). Works for inserts, edits and deletes with their cascades (server test). Notes, whiteboard files and the Today session are still not undoable, so not redoable either.

### Unresponsive buttons, and tests for them (done 2026-10-28, reported by Paddy: "Mark done is unresponsive")
- Two causes found, both reproduced with a slow fake server in real Chrome. (1) Several buttons only changed the screen after Google replied (1 to 3 seconds, longer behind other saves; every save waits in one queue), so they looked dead: project Pause, Resume, Mark done and Reopen, the Today session Start, Pause and Resume, the daily minimum, and Undo and Redo. (2) A new sticky note was placed at a fixed spot near the top of what you could see, which could be right on top of the project's Edit, Lock, Pause and Mark done buttons, so taps hit the note. This is the most likely cause of what Paddy saw.
- Fixes: `FT.optimistic(apply, send)` shows the change at once and saves in the background; if the save is refused the screen goes back and the error shows. Used for project status (with an Undo message), session Start, Pause and Resume, and the daily minimum. Undo and Redo show "Undoing…" and "Redoing…" at once, and Redo needs a connection like Undo. A bar along the bottom of the header shows whenever anything is waiting for Google (after 0.2 s; still in E-ink and with reduced motion). New sticky notes now go to the spot nearest what you can see that covers no button, field or other note (looking down the page, then up) and scroll into view if that is off screen.
- Tests: `tests/browser.test.js` (in `npm test`, skips without Chrome) at 1280 px and phone size with a 900 ms server: every listed button must show something within 300 ms, the change must reach the server, a refused save must roll back with the reason, a hung call must not stop buttons responding, nothing may cover the visible controls, and a new sticky note must not land on the project buttons. `tests/support/devserver.js` serves the real page over the real server code with adjustable delay, held calls and refused calls. It was checked by putting the old Mark done behaviour back, which made it fail.
- Not optimistic (they still wait, with the bar and the dot showing): the pomodoro button (the server works out the period), Finish session, Swap focus, and the dialogs' own Save buttons.

### Lost notes text (done 2026-10-29, reported by Paddy: "text written in the notes editor, you press done and move on and it wasn't saved")
- Reproduced in `tests/saving.test.js` (jsdom) and in real Chrome (`tests/browser.test.js` part 6, which failed on the old code). Causes found and fixed:
  - Nothing was sent when the page was hidden or closed within the 1.2 s save delay. Now every keystroke keeps a draft on the device (`ft.draft.notes.<mode>.<project>`, localStorage), the next visit puts it back and saves it, and hiding or closing the page saves at once (`FT.onLeave`, also used by sticky notes and before a mode switch).
  - A page left open on another device wrote its old notes over newer ones. Every save now carries the version it builds on; if the file changed since, the newer edit wins and the other text is kept as a conflict copy in the Notes folder, with a message and a Log line. The same text is not a conflict. A page whose data had no notes row for the project loads the file before its text can replace it.
  - Failed saves were silent and never retried. Now an error message with "Retry now", automatic retries (2 s, 5 s, 15 s, 30 s, then every minute), and the draft stays on the device.
  - `FT.htmlToMd` dropped text inside list items that held a heading or paragraph (Chrome makes that when H1/H2 is pressed in a list). It keeps the text now.
  - A late notes load could replace text typed meanwhile; it is ignored while typing. Notes changed elsewhere are loaded again when the project opens.
  - Other editors: the card dialog warns once before a tap outside or Esc throws away changes; a sticky note no longer goes back to older text when the reply to an earlier save arrives.
- Not checked on Google's runtime or a real phone: whether a save started while the page is being hidden gets out (the draft covers it if not).

## Known gaps and untested assumptions
