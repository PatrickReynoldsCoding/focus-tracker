# Roadmap and decisions

Handoff notes so a fresh Claude session has the context this project was designed with. The owner is Paddy.

## Why this exists

Paddy juggles several coding projects, job-search goals and house maintenance, and loses track of anything he has not touched for a few days. He picks work on feel each morning and wants structure. The app picks one focus project per day, shows its next action and last note, and makes stopping cheap: one line on where he stopped, then he can let it go.

## Constraints and preferences

- Free to run: Google Sheets + Apps Script, deployed as a web app only he can open. Works on every device. Desktop is the main target, phone should be usable.
- Frictionless: open it and it works. Few clicks.
- Separation of concerns, plugin style: a small core and one folder per feature. Adding or removing a feature is a folder plus one config line. See AGENTS.md.
- Data readable by humans and by Claude: sheet tabs and plain markdown notes, no opaque blobs.
- Never link or copy sensitive Drive material. See AGENTS.md. Never commit his real links or ids.
- Excalidraw whiteboards per project (done, 2026-10-28; named, several per project since the Settings change): whiteboard module. React 18.2.0 and @excalidraw/excalidraw 0.17.6 load from jsDelivr only when a whiteboard opens. Saves `<mode folder>/Whiteboards/<project>-<id>.excalidraw` two seconds after a change and on close; reopens where you left off. Checked in real Chrome (draw, autosave, close, reopen).
  - Phone (2026-10-28): the desktop-only gate is gone. Excalidraw 0.17.6 has its own touch layout (top toolbar, bottom menu with undo/redo, hand tool). Tested with finger drawing (rectangle and freehand), pinch zoom, autosave, Save and close, and reopen, in Playwright Chromium mobile emulation (393x851, touch) and in real Chrome 124 on the Android 10 emulator (`com.android.chrome`, driven over DevTools). The page does not zoom or scroll sideways. The whiteboard bar is one slim line on phones; `touch-action: none` and `overscroll-behavior: none` on the shell stop pull-to-refresh while drawing. Not checked on a real phone: palm rejection, stylus, the on-screen keyboard with the text tool, and long-press behaviour. The Excalidraw menu still shows its own GitHub/Discord/Twitter links and "Reset the canvas", as on desktop.

### Batch 1: quick wins (done, 2026-10-28; tested with fakes only, not yet on Google's runtime)
Decisions Paddy made while it was built:
- Pomodoro breaks count as session time. Only Pause stops the session clock (and the pomodoro).
- When a work or break period ends, it alerts and then waits for a click ("Start break" / "Start work"). It does not move on by itself.
- The pomodoro is off by default and is switched on per session. Lengths are kept in user properties. A changed length applies from the next period.
- The Log has a `minutes` column: worked minutes without pauses, written on finish.
- The alert ticks on every tab while a session runs, not only on Today.
- No browser notifications: Chrome denies them inside the Apps Script iframe (tried 2026-10-28, even with the permission set by hand). Instead a period ending plays a sound made with Web Audio: a chicken when work ends (break starts) and a steam whistle when a break ends (work starts). The Pomodoro lengths dialog has buttons to try both. The tab title still blinks.

Original requests:
- Desktop: a small icon at the right to stretch the page to full screen width (remember the choice per browser).
- Projects table: sortable and filterable (by category, status, text).
- Kanban: remove the single "new task" bar. Each column has its own add-task control.
- Today: when a session is started, allow pause, and a simple pomodoro timer (work/break lengths configurable, default 25/5). Session time excludes pauses. State is stored server side so it survives switching devices. Alert with sound and tab title, because browsers may block notifications inside Apps Script pages.

### Local cache, offline queue, last page (built 2026-10-28, requested by Paddy; checked in jsdom and real Chrome, not on Google or a phone)
- The page remembers the page it was on (tab or project, per mode) in this browser only, and a reload returns to it. A deleted or locked project falls back to Today. Switching mode starts on Today.
- A saved copy of each mode's data (IndexedDB, then localStorage, then memory) draws at once with "Updating…" while the fresh data loads, and is ignored if its `SCHEMA` number differs.
- While the connection is down, card, checklist, sticky note, list, notes and project edits are kept on the device (queue survives a reload), shown as "Offline · N waiting", and sent in order when it returns. Anything else says "You are offline" and is not queued.
- Rows carry `updated_at` (Projects, Tasks, Criteria added to the sheet automatically). A queued edit that finds its row changed elsewhere keeps the newer version and logs the other in the Log tab; notes keep the older text as a conflict copy file. Details and limits: docs/offline-design.md.
- The honest limit: Apps Script serves the page, so it still cannot open cold with no signal. That needs the GitHub Pages route (docs/future-github-native-spike.md and the wrapper site).
- Untested on real devices: what `google.script.run` does with a dead connection (the code treats network-like messages, `navigator.onLine === false`, or 30 seconds without an answer as offline), and whether browser storage survives between visits inside the Google sandbox on the phone.

### Redo for data changes (done 2026-10-28, requested by Paddy)
- The header has Redo next to Undo (Ctrl or Cmd + Shift + Z, or Ctrl + Y). Undoing a change records the opposite change while the rows are put back, and keeps it in the same Undo tab as a row with `kind` = `redo` (new column, added automatically). Redo puts it back and returns the change to the undo list. Any new change clears the redo rows (no extra sheet read: `saveUndo_` already reads the tab). Works for inserts, edits and deletes with their cascades (server test). Notes, whiteboard files and the Today session are still not undoable, so not redoable either.

### Unresponsive buttons, and tests for them (done 2026-10-28, reported by Paddy: "Mark done is unresponsive")

### Lost notes text (done 2026-10-29, reported by Paddy: "text written in the notes editor, you press done and move on and it wasn't saved")
- Reproduced in `tests/saving.test.js` (jsdom) and in real Chrome (`tests/browser.test.js` part 6, which failed on the old code). Causes found and fixed:
  - Nothing was sent when the page was hidden or closed within the 1.2 s save delay. Now every keystroke keeps a draft on the device (`ft.draft.notes.<mode>.<project>`, localStorage), the next visit puts it back and saves it, and hiding or closing the page saves at once (`FT.onLeave`, also used by sticky notes and before a mode switch).
  - A page left open on another device wrote its old notes over newer ones. Every save now carries the version it builds on; if the file changed since, the newer edit wins and the other text is kept as a conflict copy in the Notes folder, with a message and a Log line. The same text is not a conflict. A page whose data had no notes row for the project loads the file before its text can replace it.
  - Failed saves were silent and never retried. Now an error message with "Retry now", automatic retries (2 s, 5 s, 15 s, 30 s, then every minute), and the draft stays on the device.
  - `FT.htmlToMd` dropped text inside list items that held a heading or paragraph (Chrome makes that when H1/H2 is pressed in a list). It keeps the text now.
  - A late notes load could replace text typed meanwhile; it is ignored while typing. Notes changed elsewhere are loaded again when the project opens.
  - Other editors: the card dialog warns once before a tap outside or Esc throws away changes; a sticky note no longer goes back to older text when the reply to an earlier save arrives.
- Not checked on Google's runtime or a real phone: whether a save started while the page is being hidden gets out (the draft covers it if not).

Label "Notes" (no project link), phone chip "Notes"; Add feature and its window title call it "Today notes", so it is not mistaken for a project's notes. Removable and re-addable like before.

### Today pills and Today settings on a phone (done 2026-11-14, requested by Paddy after the mockups, option A "list and edit sheet"; jsdom and real Chrome at 393 and 1280 px with the fakes, light, dark and E-ink; not on Google or a real phone; not deployed)
- **Pills replace the chips** on a phone's Today (up to 760 px). A pill is a name (up to 24 characters), an optional icon (one of ten emoji, or none) and any number of Today panels in an order. Tapping a pill shows all its panels one under the other. The same panel may be in several pills. The pinned focus stays above the row of pills; ⚙ sits at the end of the row and stays on screen however many pills there are (the pills scroll).
- **What a pill can hold:** every Today panel but the pinned focus (also ones removed from the desktop's Today), plus every list and whiteboard of the mode, one by one, also those not shown on the desktop's Today. They come from the new slot `today.pillPanels` (lists and whiteboard modules) through `FT.layout(..., { pager: { offPage } })`; a panel says its `kind` (`list`, `whiteboard`, else a panel) so the editor can group them. A whiteboard shown only in a pill has no "+ Today" chip. A panel that no longer exists (a deleted list) is left out quietly; a pill left with no panels says so, with Add panels. A pill whose panels have nothing to show right now (Not touched on a day nothing is stale) is left out of the row, as the chip was.
- **Counts** come from the pill's panels, as the chips' did (To-dos open, Habits done/active, Not touched), joined with " · ".
- **Swipes** keep the pager's rules: a swipe on the panels changes pill and stops at the first and last pill; the pinned focus, the row and the strip under the bar still change tab. Changing pill draws the page again (only the chosen pill's panels are on the page, so a panel in two pills never has two copies with the same element ids); a field being typed in is left first so it saves. Changing pill scrolls only the row, never the page sideways (a bug found in Chrome: `scrollIntoView` moved the whole page and hid ⚙).
- **Today settings** (⚙, "Today settings" in the phone's ☰ menu, or the button in Edit layout) is drawn in Today's place, with ‹ and Done; the phone's back button and Esc close it too. It has: the pills as cards (name, icon, the panels as tags; drag ⠿ with a finger or mouse, or ▲ ▼; Edit), + New pill; Quick add; Focus card size; the pill row's switches. Edit and New pill open a sheet (`FT.dialog` with the new `sheet` and `headButton` options, so it keeps the dialog's focus trap, Esc and the "unsaved changes" warning on a tap outside): Name, Icon, "In this pill, top to bottom" (▲ ▼ ✕), and Add grouped as Panels, Lists and Whiteboards. Delete is beside the title and shows the usual Undo message. An empty name falls back to the first panel's name ("New pill" if it has none). At most 12 pills: + New pill and Quick add are greyed at 12.
- **Quick add:** Routine (Habits, To-dos), Shopping (a list whose name has "shop" or "grocer", else the first list, and To-dos), Thinking (Today notes and the first list), Week (Weekly rotation and Not touched). Only templates whose panels exist are offered, so a mode with no lists has no Shopping or Thinking. Decision: "Plan my week" is a button in the Weekly rotation panel (and Habits), not a panel, so Week holds the rotation and Not touched.
- **Focus card:** Compact (the pinned short card with More, as before), Full (the whole focus panel, no More) or Hidden (no focus card on Today; the corner timer still runs during a session).
- **Switches:** Show counts on pills, Swipe between pills (off: a swipe on the panels does nothing, it does not change tab either), Open on the pill I used last (off: the app, or a mode, opens on the first pill; within a page load the chosen pill is kept either way). The pill last used stays per device (`ft.pager.<mode>.today`, the chips' key, so the chip chosen before is still chosen).
- **Storage:** per mode, in the mode's Settings tab through the layout module, so every phone shows the same: `layout.today.pills` = `[{"id","name","icon","panels":[...]}]` (`layout.savePills`, the whole list each time) and the switches as view choices in `layout.today.view` (`focusCard`, `pillCounts`, `pillSwipe`, `pillLast`; `layout.saveView`, which now checks their values). The server checks names (1 to 24 characters after trimming), at most 12 pills, a known icon, unique pill ids, and panel ids that look like panel ids (`[a-zA-Z0-9_-]`, up to 40 a pill, each once). Every change shows at once and is saved behind (`FT.pills.save` / `setView`, `{ render: false }`, `FT.saveFailed`).
- **Undo:** pill changes and deletes can be undone and redone. Settings rows have no id, so the change journal has a new kind of change, `setting` (key and value before), written by `setSettingsWithUndo_` (core/settings.js) and put back by `revertChanges_`. Only `layout.savePills` uses it; the switches, phone order and desktop layout stay out of undo as before. Undo of the first save takes the row back to empty, so the pills made from the panels come back.
- **Default and migration:** with no pills saved, each panel on Today (not removed) is its own pill, named after it (its short name), in the phone's order, with the panel's id as the pill's id. Nothing changes on screen until Paddy edits; the first change saves the whole list. More than 12 panels: the 12th pill ("More") holds the rest.
- **Desktop and phone:** the desktop's Today is unchanged: its grid, Remove and Add feature still decide what the desktop shows. Pills decide what a phone shows and are independent of the desktop: a panel removed on the desktop can still be in a pill, and a list in a pill does not need "On Today". Removing a panel on the desktop does not touch the pills; deleting a list or whiteboard leaves it out of every pill. "Reset this page" on the desktop leaves the pills.
- **What it replaces on a phone:** the chip row and its press-and-hold reorder (gone), and Edit layout's ▲ ▼ and Remove for Today: on a phone's Today, Edit layout says the pills are arranged in Today settings and has a button for it. ▲ ▼, Remove, Add feature and press-and-hold still work on every other page; `layout.today.phone` is still read for the default pills.
- E-ink: 2 to 3 px black borders, black switches and chosen buttons, no motion (the drag jumps from place to place). Dark: the app's tokens. Every target 44 px.
- Not done: pill changes are not in the offline queue (offline they fail with the usual message); there is no keyboard way to move a panel inside a pill other than ▲ ▼ in the sheet (that is the keyboard way).
- Tests: server (saved per mode as one readable row, cleaned, kept by a desktop reset; 12 pills, names, icons, ids, panel ids checked; undo and redo of saves, the first back to no row; the switches' values), jsdom (Edit layout on Today points to Today settings while a project page keeps ▲ ▼; default pills from the phone order with counts; swipes and keys; holding a pill does nothing; ⚙, the ☰ item, Done, back and Esc; a new pill with Habits and a list not on Today, ▲ ▼ in the sheet, saved, stacked, not on the desktop; ▲ ▼ and a pointer drag of the cards; edit with an empty name, delete with Undo; Quick add and the Work mode with no lists; a deleted list left out and an empty pill's Add panels; the three switches with a mode switch for "the pill used last"; the three focus card sizes and the corner timer while hidden), real Chrome at 393 px (a pill tap and swipe, ⚙ on screen with many pills, a touch drag by ⠿, the sheet's adds and Add pill within 300 ms and on the server, the pill's panels stacked; Edit layout's button on Today and ▲ ▼, Remove and Add feature on a project page).
- Not verified: a real phone (touch drag of ⠿ in Google's iframe, emoji in the E-ink reader's font), Google's runtime.

### The Notes tab: notes, lists and to-do lists (done 2026-11-14, requested by Paddy; tested with fakes, jsdom and real Chrome at 1280 and 393 px; not on Google or a real phone; not deployed)
Paddy's answers: notes are "standalone + project notes with filter to show/hide project notes"; "the concept of Today notes should be removed, Today simply has the ability to show any note"; to-do lists are "each list with its own panel, but also each to-do list can be grouped similar to how lists currently work", with "the same pop-out card details as lists".
- **The Lists tab is now Notes** (same module `lists` and page key `lists`, so saved layouts and the `list-<id>` panel ids are kept). It shows every row of the Lists tab in its order, by kind: a list, a to-do list or a note, then (unless "Show project notes" is off) one panel per project that has notes, after them, by project name (archived projects left out). The intro panel has + New note, + New list and + New to-do list (a name, then shown at once with a browser id and saved behind; the Notes tab's + New list no longer waits for Google). "Show project notes" is on by default and kept per mode in Settings (`layout.lists.view = {"projectNotes":"off"}`), like the Projects tab's status filter. Decision: on by default, as Paddy described the tab as standalone plus project notes with a filter to hide the latter; each shown note loads its Doc (one call per note, in parallel), so a mode with many projects pays for that the first time the tab opens.
- **Notes that belong to no project** are rows of the Lists tab with `kind` `note`, so name, colour, order, Show on Today and Linked project work like a list's. Each is its own Google Doc named after it in the mode's Notes folder (a Notes row with `list_id`), edited with the same editor, saves, drafts, versions and conflict copies as a project's notes. Renaming renames the Doc; Delete asks first, puts the Doc in Drive's bin and can be undone (the Doc comes out of the bin when the note is next read). Details: docs/notes-docs.md "Notes of the Notes tab".
- **Today's own note is gone as a concept**: no reserved `today` key, no Today-only panel. Any note (a note of the Notes tab, or a project's notes, panel `pnote-<project id>`, `notes.setShowToday`) can be a Today panel (Add feature) and be in a pill.
- **Several notes on screen at once**: the editor's element ids carry the note's key, so the Notes tab and Today can show several editors. The pop-out rule is now per note (`data-one-copy="note:<key>"` in a panel's html): while a window shows some notes, any other panel with the same notes shows a placeholder; other notes draw as usual (before, any notes window blocked every other notes panel).
- **To-do lists**: a row of the Lists tab with `kind` `todo`, any number of them, each its own panel (Notes tab, Today, a pill, a project's page). Its groups are its board columns, made, renamed, dragged and deleted with the same controls as a list's groups (the header shows only from two groups on, so a one-group list looks like the old To-dos panel; deleting a group moves its to-dos to the group beside it). Each group has its own add box with Today / Tomorrow / Anytime. To-dos drag between the groups of their list (SortableJS, `todos.move`). On Today a list shows its to-dos due by today and anytime, and the ones ticked today; elsewhere also those for later days. Plan my week covers to-dos of every list and adds to the first.
- **A to-do opens the card dialog** (the kanban module's, now `FT.kanban.openCard`, not a copy): title, group, colour and the rich-text description, plus the to-do's When (anytime, today to the end of next week, or its own passed day), Project and Done. One call, `todos.update`, undoable, queueable offline with conflict checks (`CONFLICT_TARGETS_`). The description is kept as cleaned `note_html` with a plain copy in `note`.
- **The pill sheet makes them on the spot**: under Add, "Make one" offers + New list, + New to-do list and + New note; a name box and Create (or Enter) make it at once (`FT.lists.create`) and put it in the pill being edited; Save then saves the pill as usual. The sheet groups what can be added as Panels, Lists, To-do lists, Notes and Whiteboards. Quick add's Routine and Shopping use the first to-do list (Shopping one whose name has "shop" or "grocer" first), Thinking the first note.
- **Storage and migration (schema v6)**: Lists `kind`; To-dos `list`, `group`, `color`, `list_id`, `group_id`, `note_html`; Notes `list_id`, `show_today` (docs/schema.md). Each mode's to-dos become the to-do list "To-dos" with one group "General"; Today's note becomes the note "Today notes" (same Doc); both on Today, and Today's saved layout, phone order and pills point at their new panel ids, so nothing moves or disappears. A save for the old key `today` from a page loaded before the update still reaches the note. Run `migrateAllModes()` from the Apps Script editor after pushing.
- **Decisions to know**: a new mode starts with no to-do list (the first to-do added, for example from Plan my week, makes "To-dos"); a to-do list's first group is called "General"; deleting a to-do list deletes its to-dos (with Undo); the card dialog's toolbar found the first `.rtbar` on the page, which on a project page was the notes toolbar (so its buttons did nothing there): it now looks only inside the dialog.
- Not done: no keyboard way to move a to-do between groups other than the card dialog's Group; a popped-out "Today notes" window saved on a device before the update shows "cannot be shown here" once (Close window); project notes have no "Show on Today" button on the Notes tab (use Add feature on Today).
- Tests: server (notes of the Notes tab: Doc, rename, conflicts, per mode, delete and undo out of the bin; project notes on Today; several to-do lists, groups, moves, group delete and undo, list delete and undo, card fields, typed rows, an offline conflict), migrate (v6 with layouts, phone order, pills, the old `today` key, an old Small tasks layout, idempotent), jsdom (the Notes tab, + New note, the project notes filter, a note on Today through Add feature, the to-do card dialog, a second to-do list with groups and drag, the pill sheet's Make one, per-note pop-out placeholders), real Chrome (a note on Today saves to its Doc; + New note, + New to-do list, the filter, a to-do's card, the pill sheet's + New note and + New to-do list answer within 300 ms and reach the server).
