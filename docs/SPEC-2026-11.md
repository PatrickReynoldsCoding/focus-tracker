Everything stays in the user's Google Sheets and Drive, so an assistant with a Google connector can make and edit projects. With the `drive.file` scope the app only sees files it made, so assistants add rows to the app's sheet and write into the app's notes Docs instead of making new files.

## How the daily minimum works today

- It is a category, chosen in Today → Weekly rotation → Edit ("Daily minimum panel"). Personal defaults to Job search, Work to none.
- The panel shows the first active project in that category in Projects sheet row order, skipping today's focus unless it is the only one.
- "Mark today's 10 minutes done" flips a yes/no flag for the day in user properties. It is not logged, does not touch the project, and has no history. Nothing times the 10 minutes.

## Requirements

### Kanban
- Columns can be moved by click and drag, like cards.

### Assistant integration
- An assistant (Claude or any other) can add or update projects directly in the spreadsheet through a Google connector, without breaking the app.
- It knows the ins and outs of the app and the sheet, so it puts things in the right place. Example: a project's GitHub repo goes into its resources automatically.
- "Save all these notes in Focus Tracker" works in a chat about a project.
- Tested first on mock data.
- Approach: (1) a Google Doc "Focus Tracker – guide for AI assistants" in the root of the Focus Tracker Drive folder, written by the app from the code so it never goes stale; (2) a "Start here" tab at the front of every spreadsheet with the short version; (3) Settings → "Set up your AI assistant" copies a paragraph to paste into the assistant's memory or project instructions. Rows an assistant adds without an id, order or created date are completed by the app on the next load; bad rows are flagged in a `problem` column, not dropped.

### Resources
- Resources have groups.
- Not just links: phone numbers, email addresses, plain text and Drive files too.
- The add dialog can choose a file from Google Drive (in-app Drive search; the owner picks the file, so the AGENTS.md rule holds; the sensitive-file warning stays).

### Google integration
- Project notes backed by a Google Doc instead of markdown, called `<project name> notes`, in the root of the project's folder, opened with "Open in Docs". Only if it does not slow the app down: measure on Google first. If the Doc write is slow, keep the fast path and update the Doc on Done or page leave; if even that hurts, drop it and say so.

### Notes formatting
- Ctrl+Alt+1/2/3 for heading 1 to 3, Ctrl+Alt+0 for normal text (Cmd+Alt on a Mac). In the project notes and card notes.

### Linked projects
- Projects can be related, as in Jira. Example: project 1 needs project 2 done before it starts.
- A project blocked by an unfinished project is left out of the focus pick, like a lock, and shows "Waiting on <project>".

### Lists and whiteboards
- A list can be linked to a project and then shows on that project's page.
- Whiteboards get their own tab. A whiteboard does not need a project.
- A whiteboard can be shown on Today.
- Whiteboards show a small thumbnail instead of only the name.

### Excalidraw
- "Close without saving".
- Settings: a favourite tool, selected when a whiteboard opens.

### A spreadsheet people can read
- Tabs that hold information for people (projects, resources, lists, habits) are bright and first. Tabs only the app uses are grey and last.
- One data structure for the whole sheet, as small and readable as possible, covering every feature in this spec. Designed in `docs/schema.md` and approved before the migration.
- The migration copies the spreadsheet first (`Backup <date>`).

### Offline start
- The app opens and works when the device starts with no signal and the app was not open. This cannot be done on Apps Script (Google serves the page). It comes with the standalone app.

### Header
- Remove Back, Undo and Redo from the top bar. A settings icon holds them as the first options. Keyboard shortcuts and the phone's back keep working. The note editors keep their own Undo and Redo.
- Every delete shows the Undo message, as sticky notes do now.
- A setting to open on Today instead of the last page (per device).

### Saving
- Text typed in the notes editor was sometimes lost after pressing Done and moving on. Reproduce it with tests, then fix it. Check the other editors too.
- Causes found (most likely first): no save when the page is hidden or closed within the 1.2 s timer; a stale page on another device overwrites newer notes (online saves send no base version); failed saves are silent and never retried; `FT.htmlToMd` drops headings or paragraphs inside list items; a late notes load overwrites newer text; a saved copy without a notes row overwrites the whole file; the card dialog throws away text on an outside tap or Escape; a sticky-note reply can bring back older text; a mode switch inside the timer saves into the wrong mode.

### Standalone app
- Removes the Google banner. Free, with donations. Others can use it: download or install, sign in with Google, and it works, with no Apps Script for the user. Updates itself.
- Spike first (`docs/standalone-app-spike.md`): a PWA on GitHub Pages with Google sign-in and the Sheets and Drive APIs (the `drive.file` scope avoids the heavy Google verification), offline start with a service worker, automatic updates, Electron or Tauri as the alternative, and reuse of the current module code in the browser.

### Projects tab
- The status filter allows several statuses and is remembered per device.

### Today, habits and Insights
- Today has a main focus (where the brain goes today, for example house renovation or a coding project) and small tasks: repeating ones (30 minutes of job hunting, 10 minutes of fitness) and one-off ones (grocery shopping, a job interview). Tap them off as done; see per week how often each was planned against done.
- "Plan my week", one week ahead at most, so it does not become a calendar. Google Calendar is not ruled out for later.
- Habit tracker: n sessions a day or week. A new habit has a name, a description and an intention (strict, "5 cardio sessions a week", or loose, "just trying it out"). The app advises starting low and building up (think Couch to 5K) and offers prompts every n days or weeks to increase frequency or duration. Answers: "Yes, adjust", "Not now", "I'm at my goal" (stops the prompts).
- Today has a small habits panel: the habit name, perhaps the intention, and a row of dots for the sessions. Tap a dot for one session; more taps than dots count as extra.
- The Log tab becomes Insights with sub-tabs, Logs being one. Insights show progress against goals, over goal, and so on.
- Ideas from other habit trackers and HTML mockups come first (`docs/habits-ideas.md`, `docs/mockups/`), for approval before building.
